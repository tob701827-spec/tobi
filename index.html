Introducción

El video es un tutorial práctico de Supabase, una plataforma open source que se presenta como alternativa a Firebase. Muestra cómo crear un proyecto, armar una tabla llamada products y usar la API REST que se genera sola para leer, agregar, modificar y borrar datos.

En la segunda parte explica la seguridad: cómo activar Row Level Security (RLS) y crear políticas para decidir quién puede hacer cada operación. También prueba la API con Postman y observa el contenido de un token JWT.

Conceptos fundamentales

Supabase

Plataforma de backend que ofrece base de datos, autenticación y API sin tener que programar un servidor propio.

PostgreSQL

Base de datos relacional donde se guardan las tablas. Es el motor que Supabase usa por debajo.

PostgREST

Herramienta que lee las tablas y crea automáticamente los puntos de acceso de la API REST.

API REST

Forma de trabajar con datos mediante peticiones HTTP: GET (leer), POST (crear), PATCH (modificar) y DELETE (borrar).

Row Level Security

Reglas que definen qué filas puede ver o cambiar cada usuario. Sin ellas, la tabla queda desprotegida.

Cuestionario resuelto

1. ¿Cuál es el tema principal del video? Explica de qué trata.

Trata sobre cómo usar Supabase, una alternativa open source a Firebase. Muestra cómo crear un proyecto con base de datos Postgres y usar su API REST automática para leer y modificar datos.

2. ¿Qué problema o necesidad tecnológica se aborda?

Montar un backend (base de datos, API, usuarios) lleva mucho tiempo. Supabase lo da armado, y además enseña a proteger los datos para que no cualquiera pueda modificarlos.

3. ¿Cuáles son los cinco conceptos más importantes? Define cada uno.

  • Supabase: plataforma de backend con base de datos, autenticación y API.
  • PostgreSQL: la base de datos relacional que usa por debajo.
  • PostgREST: herramienta que crea la API REST automáticamente desde las tablas.
  • API REST: forma de operar datos mediante peticiones HTTP (GET, POST, PATCH, DELETE).
  • Row Level Security (RLS): reglas que definen quién puede leer o modificar cada fila.

4. ¿Qué herramientas, programas o tecnologías se mencionan y para qué sirven?

  • Supabase: backend (base de datos, API y usuarios).
  • Table Editor y API Docs: crear tablas y ver ejemplos de cada petición.
  • Postman: probar la API enviando peticiones.
  • jwt.io: ver qué contiene un token JWT.
  • Navegador web: manejar el panel de Supabase.

5. ¿Qué procedimientos o pasos se explican? Preséntalos en orden.

  1. Crear la cuenta, la organización y el proyecto.
  2. Ver las claves y la URL de la API.
  3. Crear la tabla products con sus columnas.
  4. Cargar filas de prueba.
  5. Probar la API desde Postman.
  6. Activar RLS y crear políticas.
  7. Probar insertar, actualizar y borrar con y sin permiso.

6. ¿Qué ejemplos prácticos aparecen? Explica uno detalladamente.

Se hace una petición GET desde Postman a la URL de la tabla products, enviando la clave apikey en los encabezados. La API devuelve las filas en formato JSON (por ejemplo laptop, monitor, mouse gaming y teclado). Con la política de lectura activa se pueden ver los datos; sin ella, la tabla aparece vacía.

7. ¿Qué conocimientos previos son necesarios para comprender lo explicado?

Qué es una base de datos y una tabla, nociones de HTTP y JSON, y qué es una API. Ayuda saber algo de SQL.

8. ¿Qué ventajas o beneficios ofrece la tecnología o procedimiento?

  • Crea una API sin programarla.
  • Tiene plan gratuito para empezar.
  • Incluye seguridad integrada (RLS y autenticación).
  • Permite prototipar rápido.
  • Es open source.

9. ¿Qué dificultades, errores o precauciones deben considerarse?

  • Si se activa RLS sin políticas, no se devuelve ningún dato.
  • No exponer claves secretas (usar solo la clave pública en el cliente).
  • Escribir bien las políticas para no dar permisos de más.
  • Cuidar los tokens JWT y su expiración.

10. ¿Cómo aplicarías lo aprendido en un proyecto informático real?

En una app con usuarios, por ejemplo un sistema de inventario o una tienda. La tabla guardaría los productos, la API se los entregaría al sitio web y RLS haría que solo los usuarios autorizados puedan editarlos.

11. ¿Qué parte del video consideras más importante y por qué?

La de Row Level Security, porque sin ella cualquiera con la clave pública podría leer o borrar todos los datos. Es lo que vuelve segura a la aplicación.

12. ¿Qué conocimientos nuevos adquiriste y cómo los explicarías a otra persona?

Aprendí que con Supabase se crea una base de datos y una API lista en minutos, y que hay que controlar el acceso con políticas. Se lo explicaría así: "Es como una planilla en la nube que tiene su propia puerta de acceso. Vos decidís quién puede mirar y quién puede cambiar cada fila."

Aplicación práctica

Un procedimiento que aprendí es leer los productos de la tabla desde la API y protegerla con una política. Así se haría:

  1. Crear la tabla products con las columnas id, created_at y name.
  2. Activar RLS en la tabla.
  3. Crear una política de lectura (SELECT) para que todos puedan ver los productos.
  4. Enviar una petición GET con las cabeceras apikey y Authorization.

Ejemplo de la petición (con datos de muestra):

GET https://TU-PROYECTO.supabase.co/rest/v1/products?select=*
apikey: TU_CLAVE_PUBLICA
Authorization: Bearer TU_CLAVE_PUBLICA

Qué operación corresponde a cada método HTTP:

MétodoAcciónEquivale a
GETLeer filasSELECT
POSTAgregar una filaINSERT
PATCHModificar filasUPDATE
DELETEBorrar filasDELETE
Precaución: en un proyecto real, la clave de servicio (service role) nunca debe ir en el código del navegador.

Conclusión personal

Este video me mostró que hoy se puede tener una base de datos con su API funcionando en pocos minutos, sin armar un servidor desde cero. Me pareció muy útil porque en un proyecto de informática ahorra mucho tiempo y permite concentrarse en la parte visual y en la lógica del sistema.
